# Illusion of Gaia Companion

Read HANDOFF.md first, then OPEN-WORK.md (what is unfinished, unfixed or
untested) and the current baseline audit. Continue from receipts;
do not redo completed audits or recreate validation archives without a reason.

Current priority: full-game visual coverage and approved GaiaLabs maps with
Retranslation built into the main content, before returning to native gaps.
Fix neighboring rooms and transitions too; scene admission is not visual approval.

- Work only in this project. Lagoon, EarthBound and shared Companion projects
  are read-only references unless the owner explicitly requests changes there.
- Preserve Babel author mr0ta / mrOt4, every existing upstream credit and all
  applicable license notices. This fork is a noncommercial enhancement.
- Track current SNESRecomp with explicit source identity and preservation of
  Babel-specific changes. Never replace the vendor tree without a delta inventory.
- Keep interpreter/reference paths available. Generated C is not native coverage;
  distinguish source, build, structural analysis, bounded execution and campaign proof.
- Native area testing must also inspect the complete player-facing picture at
  the actual widescreen/extent/filter settings. Check movement in both axes,
  expanded edges, parallax, transitions, menus and relevant combat/boss phases.
  Native-viewport pixel parity and CPU comparisons alone are not visual approval;
  record visual failures even when structural checks say the renderer is ready.
- Never commit ROMs, ROM-derived generated source/binaries, saves, states,
  soundtrack packs, game screenshots or private validation data. Do not blanket-add
  the workspace; inspect the staged diff and tracked-file list before pushing.
- Keep one bounded scratch batch under ignored .local/; compact completed evidence.
- Use shared CompanionLauncher/CompanionAchievements contracts. Do not add UI
  options for unimplemented engine features. Preserve native settings and owner data.
- For game interface design and review, use the
  [Game UI/UX skill](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/main/skills/disciplines/game-ui-ux/SKILL.md)
  as the default workflow. Consult the
  [game development skills catalog](https://github.com/gamedev-skills/awesome-gamedev-agent-skills)
  for related tasks and the
  [Recomp UI overlay reference](https://github.com/RetroPortingToolKit/recomp-ui#in-game-settings-overlay)
  for in-game settings integration. Verify controller focus and navigation,
  overlay input capture, and UI scaling in the game.
- User authorizes source/README/repository updates on the existing fork. Releases
  and new public repositories need separate authorization. Tag builds must not
  automatically publish a release.
- Route Companion bug reports to the Companion fork. Keep confirmed defects in
  maintained dependencies on their own trackers, using an existing issue when
  it matches. Treat mrOt4's Babel repository as a historical reference for
  credit and documentation.
- Make routine decisions; investigate evidence instead of guessing. Delegate
  independent work with explicit file ownership and respect concurrent edits.
